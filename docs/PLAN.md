## 工作項目

### P1 使用者實測回報（核心新功能）
「今天下水了，實際是好／普通／差，能見度約幾公尺」。累積後校正燈號，並在潛點頁顯示「近 7 天 N 人回報」。
- 設計：回報入口（潛點頁底部＋首頁卡片）、30 秒內填完、手機單手可用、顯示回報摘要。
- 後端：`reports` 表（潛點、日期、體感 3 級、能見度、可選備註）；`POST /api/reports`、`GET /api/spots/{slug}/reports`；
  每 IP 每日限次、備註長度限制；先不做帳號。不自動改燈號，只先顯示並收集資料。
- 前端：回報表單與摘要區塊。
- 驗收：回報後立刻在該潛點頁看到；亂填（超長、連點）被擋。

### P2 本週最佳出發日
`/explore` 加「未來 7 天哪天最適合」排序（依區域與活動：潛水／衝浪）。後端已有逐日燈號，主要是前端＋一個彙整查詢。

### P3 收藏與比較（不用帳號）
localStorage 收藏潛點，首頁／explore 可只看收藏。

### P4 修正與穩定
- 前端：手機 CTA 與潛水員重疊；300～600m 生物分布；淺水海月水母偏扁；低效能裝置降級（量 FPS，低於門檻退回 CSS 漸層長頁）。
- 後端：基隆／高雄潮汐解析；排程頻率（待決定）；補 `GET /api/health` 的資料新鮮度欄位。
- 工程：拆 `engine.ts`（等階段 0 之後，先拍基準圖）。

## 角色分工
| 角色 | 負責 | 產出 |
|---|---|---|
| 首席設計師 | P1、P2、P3 的畫面與互動規格；手機版首頁 CTA 構圖 | `docs/design/*.md`（版面、狀態、文案，含手機）|
| 前端工程師 | 依設計實作 P1～P4 前端；FPS 降級 | 分支＋`tools/check.sh` 通過 |
| 後端工程師 | P1 API 與資料表、潮汐修正、測試 | 分支＋pytest 通過 |
| 測試工程師 | 每個分支的功能測試、邊界與濫用測試、跨瀏覽器／手機視窗 | `docs/qa/report.md`，缺陷分嚴重度 |
| 使用者角色（潛水員／衝浪者／新手）| 照真實情境走一遍，講「滿不滿意」 | 回饋寫進 `docs/qa/user-feedback.md` |
